VLA-Robustness-Eval 项目历程与当前进展精炼总结
更新时间：2026-07-21

======================================================================
一、项目目标与技术边界
======================================================================

项目目标：构建面向仿真机器人操作任务的 Failure-Aware Robustness
Evaluation Pipeline，训练语言条件机器人策略，并系统测绘其在视觉、
动力学、场景和时序扰动下的性能衰减与失效类型。

运行环境：
- macOS Apple Silicon M3 Max，36 GB 统一内存
- Python 3.10
- 官方 MuJoCo Python 包，最终固定 MuJoCo 3.1.1
- robosuite 1.5.2
- PyTorch + MPS
- 禁止使用 mujoco-py

当前研究对象：Panda 机械臂在三物体桌面场景中，根据语言指令完成六项任务：
- Pick Red Cube / Blue Ball / Green Cylinder
- Push Red Cube / Blue Ball / Green Cylinder


======================================================================
二、基础设施与最初 MVP
======================================================================

1. MuJoCo 最简基线
- 在代码内使用 MJCF 创建光源、地板和蓝色方块。
- 验证官方 MuJoCo Python API、mj_step 和 macOS Viewer。

2. robosuite 基线
- 成功部署 Panda + Lift。
- 修复原生 robosuite 环境没有 Gym action_space 的问题，改用
  env.action_spec 和 np.random.uniform 采样动作。
- 建立无渲染随机策略评估循环及 CSV 结果记录。

3. 单任务专家与数据采集
- 实现四阶段 Pick 专家：到达上方、下降、闭合、抬升。
- 使用真实物体和末端坐标构建 P-Control 专家。
- 开启 agentview 离屏渲染，保存图像、状态、动作轨迹。
- 完成首批 50 条专家演示，验证从仿真到训练数据的完整链路。

4. 第一代 MiniACT / MiniVLA
- 构建 ResNet + Transformer Decoder + Action Chunking 网络。
- 完成 Dataset、DataLoader、MPS 训练和闭环 OpenCV 评估。
- 逐步从单帧、4D 动作升级到状态历史、双头夹爪和 7D OSC_POSE。
- 第一代模型证明了基础空间趋近能力，但存在过早合爪、抓偏、
  抓后不抬升、推不远和 OOD 重试等问题。


======================================================================
三、多任务 VLA 基础建设
======================================================================

为了支持语言条件多任务训练，系统完成以下升级：

- 三物体同场景：红色方块、蓝色球、绿色圆柱。
- 7D OSC_POSE 增量控制：XYZ + RPY + Gripper。
- 双视角输入：agentview + robot0_eye_in_hand，均为 112 x 112 RGB。
- 17D 本体状态：EEF 位置、四元数、夹爪状态及线/角速度。
- 5 步状态历史。
- 20 步 Action Chunk。
- 冻结 DistilBERT 语言编码器。
- ImageNet ResNet50 双视角共享视觉骨干。
- BatchNorm 全部替换为 GroupNorm。
- 连续位姿回归头与二元夹爪分类头分离。
- 增加 Phase、Target Position Grounding 和 Target Class 监督。
- DataLoader 采用跨 Episode、跨任务 Interleaving，避免连续视频帧
  充满同一个 Batch。

项目早期曾采集 4800 条多任务数据，用于验证完整语言 VLA 流程。
后续发现数据数量不能代替因果正确性，因此最终版本没有继续依赖这批旧数据。


======================================================================
四、V2：六任务正式架构
======================================================================

目标：建立完整六任务、双视角、语言条件的正式 MiniVLA 架构。

主要建设：
- Stage 0：专家和场景完整性。
- Stage 1：六任务平衡采集。
- Stage 2：多模态模型和训练。
- Stage 3：闭环评估。
- Stage 4：Preflight / Postflight / 80% Gate。

首版 V2 使用 600 条平衡数据快速验证，正式闭环结果只有：
- Clean Success：12.5%，15/120。
- target_not_reached：35。
- target_not_contacted：48。
- missed_grasp：19。

根因：
- 初始状态样本比例过低，但评估总从初始状态开始。
- 普通验证 Loss 被大量容易的中段帧稀释。
- Batch 内样本仍高度相关。
- Grounding 正确不代表动作解码器真正使用了目标信息。
- 小 Batch 下 BatchNorm 统计不稳定。
- 平均动作误差无法检查 Approach -> Contact -> Lift/Push 的因果顺序。

结论：普通离线 Loss 不能作为策略发布标准。


======================================================================
五、V2.1：初始状态与 Grounding 抢救
======================================================================

主要修改：
- 初始状态窗口过采样。
- 独立 Initial-State Validation。
- 模型选择加入 Initial XYZ、Grounding、Target Selection/Class 指标。
- 强制每个 Batch 混合多个 Episode 和任务。
- 使用 ImageNet ResNet50，冻结早期层，BatchNorm 改 GroupNorm。
- 只保留颜色、轻微模糊和平移等物理语义安全的视觉增强。

结果：
- Task Success：75.83%。
- Clean Success：72.5%。
- Target Class Accuracy：100%。
- Wrong Contact：3.33%。

暴露的问题：
- 蓝球可能陷入桌面。
- Push-B 接触过高、带向上动作，推动距离不足。
- 机械臂偶尔到达边界并振荡。
- 圆柱倾倒后策略不知道如何继续。
- Pick 会抓起后放下并反复重试。

结论：架构方向正确，主要瓶颈转向接触物理、专家动作和时序执行。


======================================================================
六、V2.2：接触物理与专家稳定化
======================================================================

主要修改：
- 蓝球半径调整为 2.6 cm。
- 调整球体 friction、damping、solref、solimp，缓解穿桌和冲击异常。
- 为三类物体设置独立 Push 接触高度。
- 接触阶段保持水平或轻微向下，不再斜向上推。
- 增加抓取确认、丢失确认、Pick/Push 恢复状态。
- Push-B 扫描多个候选接触高度。
- 增加推动走廊、圆柱 Uprightness 和桌面留存检查。

采集中曾出现：Failed trajectories must use success_step=0。
修复了失败轨迹与成功元数据混用问题后，完成 1200 条平衡数据。

表现：
- 运动明显聪明、稳定，无暴力抽搐和大范围推空。
- 目标选择可靠，Pick-B/Pick-C 明显改善。
- 整体约处于高 60% 至低 70% 区间。

残留问题：
- 抓起后可能再次松开。
- 物体移动后可能回到旧位置下爪。
- Push-B 经常推不够远。
- Push-C 倾倒后缺少合理处理。

V2.2 最终成为稳定回退点和后续感知权重来源。


======================================================================
七、Stage 1 / 1.1：执行辅助实验及其废弃
======================================================================

曾实验加入：
- 检测真实抓取后锁定夹爪。
- 接触或抓取变化时清空 Action Chunk。
- 使用真实物体位置重新对齐。
- 强制 Push-B 接触高度和 Phase 7 延长。

这些逻辑在不改变模型权重的情况下显著提高可视化表现，证明模型经常已经到达
可成功状态，部分失败来自执行时序。

但这些逻辑使用模拟器真实接触、抓取或物体坐标，属于特权执行辅助，会污染
VLA 原始策略成功率。因此最终全部删除，只保留与目标无关的 EEF 工作空间和
桌面高度安全边界。


======================================================================
八、V2.3：过度复杂恢复数据导致严重退化
======================================================================

V2.3 尝试一次性加入：
- 5 步抓取确认和 5 步丢失确认。
- 强制恢复与 2-5 cm 位移后重新定位轨迹。
- 更强的 Push-B 接触高度和圆柱倾倒处理。

采集阶段暴露：
- Blue-ball push contact p90=0.0341 m，接触系统性过高。
- Preflight 检测到 Pick-C 缺少位移后重定位轨迹。

训练后出现严重回归：红块已经被夹住，但机械臂停止而不抬升。

彻查根因：
- 真实已经抓住物体时，轨迹仍保持 Phase 2 多步。
- 确认期间标签仍可能包含负 Z 或保持动作。
- 模型因此学到“抓住后继续下压/停住”，之后才看到 Phase 3。
- 强制恢复数据放大了这一矛盾边界。
- 各独立 Head 指标可以很好，但联合的 Grasp -> Lift 转移是错误的。

处理：
- 删除 V2.3 数据和权重。
- 禁止将矛盾标签混回旧数据。
- 回退 V2.2，只保留可信感知权重。

保守回退后仍偶尔出现“抓住不抬升”，说明必须重建完整因果数据链路。


======================================================================
九、V2 Clean：最终标准版
======================================================================

核心原则：每条动作标签必须描述“当前记录状态下，机器人下一步真正应该做什么”。

1. Clean Pick 状态机
- Phase 0：移动到实时目标上方。
- Phase 1：下降。
- Phase 2：闭合并确认真实双指抓取。
- Phase 3：保持闭合并抬升。
- Phase 4：释放、垂直撤退、根据实时目标重新定位。
- 一旦真实抓住，立即停止下压，最多两步进入 Phase 3。
- 真实抓取优先级高于脚本恢复逻辑。

2. Clean Push 状态机
- Phase 5：移动到实时目标后方。
- Phase 6：下降到物体专用接触高度。
- Phase 7：沿任务方向水平推动。
- Phase 8：达到真实位移阈值后保持。
- Phase 9：垂直撤退并根据实时目标重算接近点。
- Push-B 加入 30% 受控横向偏差恢复课程。

3. Collision Integrity
- Pick 双指抓取额外净空：5 cm。
- Cube/Ball Push 走廊：6 cm。
- Cylinder Push 走廊：8 cm。
- 只保存 Clean Success，丢弃错物、物理异常和语义不一致轨迹。

4. Schema 5
- 检查 shape、dtype、任务平衡、split、target ID 和 success_step。
- Pick 必须有真实 grasp，随后有 lift。
- Grasp -> Lift 延迟不得超过两步。
- 抓住时禁止打开夹爪或强负 Z。
- 首个 Phase 3 必须有正 Z、闭合夹爪和正确 Phase。

5. 最终数据集
- 版本：v2.clean。
- 共 1200 条，每项任务 200 条。
- Train 960 / Val 120 / Test 120。
- 图像 uint8，双视角 112 x 112。
- 状态 17D，动作 7D，Chunk 20。
- Preflight 四项全部 PASS。

6. 最终模型 Architecture 4
- 冻结 DistilBERT + Language Projection。
- 双视角共享 ImageNet ResNet50 + GroupNorm。
- Spatial Visual Tokens，而非单个池化向量。
- 5 步本体状态历史。
- Target Grounding / Target Class Head。
- Contact / Grasp Interaction Head，并将 Interaction Token 注入动作解码。
- Phase Head 和 Soft Phase Embedding。
- 20 个 Action Queries。
- 6D Pose Head + Gripper Logit Head。

7. 训练目标
- Pose L1。
- Gripper BCE。
- Phase CE。
- Contact/Grasp BCE。
- Grounding Smooth L1。
- Target Class CE。
- Action Smoothness。
- 专用 Pick Lift-Transition Margin Loss。

训练在 Epoch 28 早停，最终发布的是 Epoch 18 最佳权重。
最终权重：results/v2_clean/mini_vla_v2_clean_policy.pth

======================================================================
十一、鲁棒性评估框架
======================================================================

下一阶段目标：绘制成功率衰减曲线和 Failure Taxonomy。

规划的五类扰动：
1. 动态目标瞬移。
2. 视觉噪声、模糊和亮度衰减。
3. 质量、摩擦等动力学漂移。
4. 训练外 OOD 干扰物。
5. Agent/Wrist 相机外参偏移。

已完成第一阶段代码重构：
- utils/evaluation_core_v2.py：统一 EvaluationCore。
- utils/perturbations_v2.py：统一扰动生命周期及动态瞬移。
- scripts/benchmark_robustness_v2.py：多强度和双执行模式总控。
- scripts/evaluate_policy_v2.py：Clean CLI 改为复用同一核心。

框架特性：
- perturbation_manager=None 时保持纯 Clean Evaluator。
- 支持 temporal 与 latest-only 配对测试。
- 不同强度复用相同 scene seed。
- 记录 injection step/phase、actual delta、Grounding 恢复、接触延迟、
  Failure Category、成功率和相对 Clean 衰减。
- Push 评分扣除外部瞬移，禁止把扰动位移算成策略推动成果。
- 扰动可以使用真值施加和测量，但绝不使用真值辅助策略动作。


======================================================================
十二、动态目标瞬移 Pilot
======================================================================

测试设置：
- 距离：0 / 2 / 4 / 6 / 8 cm。
- 每个强度 10 Episode。
- 同时测试 Temporal 与 Latest-only。
- 当前实际控制频率为 20 Hz，不是 50 Hz。

Clean Success：
距离      Temporal      Latest-only
0 cm      100%          90%
2 cm       60%          70%
4 cm       20%          30%
6 cm        0%           0%
8 cm        0%          10%

初步结论：
- 目标类别准确率仍为 100%，语言和目标身份没有崩溃。
- Grounding 通常能在下一次推理看见新位置。
- 但动作解码器不能稳定把新 Grounding 转化为新的接近、下爪和推动轨迹。
- 当前动态重定位鲁棒半径大约只有 1-2 cm。
- 4 cm 接近崩溃点，6-8 cm 基本完全 OOD。
- Temporal 在 Clean 下更稳定，但突然瞬移后旧 Chunk 可能造成滞后。
- Latest-only 偶尔恢复更快，但小样本下尚无统计显著优势。

Pilot 发现的评估协议问题：
- 部分高强度场景改变了瞬移方向，强度曲线不完全同射线配对。
- 瞬移后只检查物体不重叠，尚未完整检查抓取通道和推动走廊。
- Reacquisition 平均值忽略未恢复 Episode，需要同时报告恢复率。
- 接触延迟应使用严格物理接触，而不是物体运动代理。
- 从未真实抓住但物体被碰高的轨迹可能误标为 insufficient_lift，
  应改为 missed_grasp 或 object_launched。

因此，该 Pilot 用于发现系统和协议问题，不能直接作为论文最终衰减曲线。

======================================================================
十四、项目核心经验
======================================================================

- 数据因果正确性比盲目增加数据量和恢复复杂度更重要。
- 低离线 Loss 不代表闭环动作正确。
- Grounding 正确不代表动作解码器真正使用了 Grounding。
- Grasp、Phase 和 Lift 必须作为联合转移验证，不能只看独立 Head 指标。
- 初始状态和关键转移窗口必须单独采样、验证和设发布门槛。
- 可视化观察对发现向上推、倾倒、边角接触和抓后释放不可替代。
- 特权状态可以用于专家、扰动施加和诊断，但不能用于最终策略执行辅助。
- 扰动评估必须严格控制场景配对、可行性和评分去偏，否则衰减曲线没有学术可信度。
- 当前 V2 Clean 是冻结参考点，后续所有鲁棒性实验必须与其比较，不能静默覆盖。
