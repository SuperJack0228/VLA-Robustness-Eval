1. 当前阶段的起点：冻结 V2 Clean 基准
===============================================================================

1.1 V2 Clean 的角色

V2 Clean 是本阶段所有后续工作的基准，而不是被覆盖或删除的旧模型。
它已经具备：

- Panda + OSC_POSE 七维动作：
  [Delta X, Delta Y, Delta Z, Roll, Pitch, Yaw, Gripper]
- 双视角视觉：
  agentview + robot0_eye_in_hand
- 5 步状态历史；
- ACT action chunk，chunk_size=20；
- ResNet50 双视角共享视觉骨干；
- 冻结的 DistilBERT 文本编码器；
- Transformer 动作解码器；
- 连续位姿回归头和夹爪二分类头；
- 六种平衡任务：
  pick_A、pick_B、pick_C、push_A、push_B、push_C；
- 完全闭环执行，不使用模拟器特权状态来替代模型动作。

1.2 V2 Clean 数据

- 数据集规模：1200 条成功专家轨迹；
- 每个任务 200 条，六任务严格平衡；
- 数据包含双视角图像、状态、动作、任务语言及任务元数据；
- V2 Clean 数据集和权重在 V3 阶段继续保留，作为不可变基准。

1.3 基准成功率的口径

历史冻结报告曾给出 V2 Clean 在 240 回合上的 93.33%。
本阶段为了和 V3 做严格公平比较，重新用完全相同的场景种子、评估代码和执行
参数测得：

- V2：222 / 240 = 92.50%

两者非常接近，但以后进行 V2/V3 对比时，应使用本阶段的 92.50%，因为这是
同协议、同种子、逐回合配对的数字。

2. 鲁棒性 Pilot 暴露的问题
===============================================================================

2.1 动态目标瞬移后的异常行为

在 Dynamic Target Displacement Pilot 中，目标物体在机械臂接近阶段被平移。
观察到：

- 位移增大后，机械臂有时仍向目标原位置运动；
- 有时丢失目标后转向其他物体；
- 抓取会在旧位置下爪；
- 推动会发生错误接触或沿错误方向继续；
- 失败后的阶段状态可能不再符合原任务。

2.2 最初假设：20 步 ACT 的历史惯性

最初怀疑主要原因是：

- chunk_size=20 太长；
- Temporal Ensembling 保留了瞬移前的动作预测；
- 旧动作在瞬移后继续被执行，导致反应滞后。

这个假设具有合理性，但后续诊断表明它不是全部原因，甚至不是 Pilot 中最主要
的失败来源。

2.3 评估协议本身存在漏洞

审查发现旧 Pilot 还混有评估代码问题：

- 瞬移方向和安全区域检查不够严格；
- 瞬移后的 actual_delta 没有完整记录；
- Push 任务可能把模拟器瞬移误计为策略推动距离；
- 碰撞对象识别和错误接触分类不够稳定；
- 某些失败会被归到过于笼统的类别；
- 缺少重定位延迟、预测年龄和接触对象等诊断字段。

这意味着旧 Pilot 结果不能简单解释为“模型的 ACT chunk 太长”。

- Temporal Ensembling 只融合仍然有效的短期预测。

这些修改仍然只使用模型观测和模型输出，不读取特权状态来生成动作。

4. Pilot 的最终诊断：问题不只是 ACT 滞后
===============================================================================

4.1 2 cm Mac 诊断测试的主要发现

在较小规模、可快速运行的 Mac 测试中：

- Temporal 模式并没有全面差于 latest-only；
- Push A 中 temporal 为 4/5，latest-only 为 3/5；
- 多数失败不是单纯“旧 chunk 继续执行 20 步”；
- 更明显的问题是目标瞬移后的视觉 grounding 漂移；
- 一旦第一次接触失败，模型可能进入训练数据稀少的恢复状态；
- 任务阶段可能发生 pick/push 家族混淆；
- 模型可能重新选择错误物体。

4.2 修正后的根因判断

当前证据支持的主要根因是：

1. 训练集中缺少目标被移动后的闭环恢复轨迹；
2. 缺少首次接触失败后的重新观察、重新对准和再次执行示范；
3. 旧语言模板固定，语义表征容易退化为六任务条件 ID；
4. 恢复状态下的目标 grounding 和 phase family 监督不足；
5. ACT 时序惯性是潜在因素，但不能单独解释所有失败。

4.3 因此没有立即把 chunk_size 从 20 改小

直接缩短 chunk 会同时改变 Clean 平滑性和基础成功率，且可能掩盖真实的数据
分布问题。因此本阶段决定：

- V3 主模型继续使用 chunk_size=20；
- 先修复恢复数据、语言增强和评估协议；
- chunk_size=[1, 5, 10, 20] 的消融实验保留为后续独立研究；
- 不在同一版本中同时改变数据、模型容量和 chunk，避免无法归因。

5. HPC 迁移与运行链路
===============================================================================

5.1 为什么迁移

Mac M3 Max 仍适合：

- 数据采集；
- 小规模 smoke test；
- 单任务可视化；
- 半小时以内的诊断评估；
- 最终闭环 MuJoCo Clean/扰动测试。

Cognition HPC 用于：

- 大规模训练；
- 多配置并行训练；
- 后续 chunk ablation；
- CUDA 加速的模型优化。

项目不是完全搬离 Mac，而是形成：

- Mac：开发、采集、可视化、短评估；
- HPC：重训练和大规模计算；
- rsync/Git：同步代码；
- 结果目录：下载回本地统一分析。

5.2 环境模块

确认可用模块：

miniforge3/25.3.0-3/none-none/a-4lhn6xy

5.3 环境冲突

最初 setup_environment.sh 失败：

- requirements 固定 mujoco==3.1.1；
- robosuite==1.5.2 要求 mujoco>=3.3.0；
- pip 判定依赖不可解。

处理原则：

- HPC 环境必须使用和项目代码兼容的一组 robosuite/MuJoCo 版本；
- 不能把 macOS 上历史依赖未经检查地直接复制到 Linux；
- 始终使用官方 mujoco，不使用 mujoco-py；
- 安装完成后以真实的 MuJoCo EGL + robosuite + CUDA smoke test 为准。

5.4 同步脚本问题

问题一：

- macOS 自带 rsync 不支持 --info=progress2。

修复：

- 同步脚本检测能力并回退到 --progress。

问题二：

- SSH multiplexing 的 ControlPath 位于很长的 macOS 临时目录；
- 超过 Unix domain socket 路径长度限制。

修复：

- 将 ControlPath 缩短到 /tmp/vla-hpc-%C。

5.5 Slurm 使用认知

- squeue 只显示排队或正在运行的任务；
- 任务完成后应使用 sacct 查询；
- Slurm stdout/stderr 和 results/runs 文件不会因终端关闭而消失；
- SSH 退出、Mac 休眠或 VPN 断开不会中断已提交的 sbatch 任务；
- 结果目录可能按 JOB_ID 命名，不能只在固定 output-dir 中查找。

- MuJoCo EGL 离屏渲染可用；

6. V3 数据方案：保留 V2 Clean，新增独立恢复数据
===============================================================================

6.1 为什么不重做全部数据

V2 Clean 已经证明：

- 六任务基础动作是正确的；
- Clean 成功率接近或超过 90%；
- 主要缺口在动态重定位和失败恢复，而不是所有专家轨迹都错误。

因此 V3 采用保守增量方案：

- 保留 1200 条 V2 Clean 数据；
- 不污染、不覆盖原数据；
- 新建 data/dataset_v3_recovery；
- 额外采集 600 条恢复轨迹；
- 每个任务 100 条，继续保持六任务平衡。

6.2 恢复数据类型

每个任务包含两类核心恢复：

1. target_displacement
   - 执行中目标发生 2、3、4 或 5 cm 的受控平移；
   - 专家必须重新读取目标实际位置；
   - 重新对准后继续抓取或推送。

2. forced_miss / recovery
   - 人为制造第一次抓取或推动未命中；
   - 迫使专家重新观察、重新定位；
   - 第二次完成正确任务。

6.3 专家逻辑修复

- 每个控制周期使用物体实时位姿，而不是只记住 reset 时位置；
- 抓取 miss offset 约 3.8-5 cm，确保真的形成恢复状态；
- Push miss 后必须重新建立正确接触；
- 动态位移后重新计算抓取或推动路径；
- 对 Push 目标同步更新 goal 和 initial_target_position；
- 同时保存 initial_object_pose，防止评分基线被瞬移污染；
- 对干扰物、工作空间边界和双侧夹爪净空做场景拒绝；
- 只保存最终成功且通过质量检查的轨迹。

6.4 数据收集中断及修复

采集到 Episode 209/600 时发生：

Blue-ball push contact is systematically too high: p90=0.0265m

这不是“已经接受的数据全部损坏”，而是一个候选轨迹违反蓝球推动接触高度约束。
V2 collector 会把这种 ValueError 当作质量拒绝并继续，V3 wrapper 当时漏掉了
这一层异常处理，因此单条坏候选终止了整次采集。

修复：

- 在 V3 采集循环捕获质量验证的 ValueError/RuntimeError；
- 打印 Quality rejected 或 Rollout rejected；
- 丢弃候选，不增加已收集 episode 数；
- 保留已经通过验证的 209 条；
- 从 summary 中恢复 attempt 和任务计数继续采集；
- 没有粗暴修改全局蓝球高度，避免制造两套不一致的专家分布。

6.5 V3 数据最终质量

Preflight 通过，关键结果：

7. V3 语言条件重构
===============================================================================

7.1 原问题

V2 训练时每种任务使用固定语言模板，容易出现：

- 同一任务的 DistilBERT 输入永远相同；
- 语言向量实际退化为六个离散任务标签；
- 模型只记住固定句式；
- 换一种自然表达后，语义泛化没有保证；
- “看起来用了语言模型”不等于真正学会语言对齐。

7.2 语言增强资源

新增：

- configs/language_augmentations_v3.json
- utils/language_augmentation_v3.py

每个任务：

- 60 条训练表达；
- 30 条与训练集合不重叠的 held-out 表达；
- 共 90 条表达。

六任务总计：

- 360 条训练语言；
- 180 条 held-out 评估语言。

表达覆盖：

- pick / grasp / lift 等动词变化；
- push / move / slide 等动词变化；
- red cube / blue sphere / green cylinder 等目标描述变化；
- 语序、礼貌形式和简短指令变化。

7.3 DataLoader 动态语言注入

- 训练时为每个窗口从对应任务的 JSON phrase pool 动态采样；
- 同一条视觉轨迹可以在不同 epoch 配不同自然语言；
- Batch 内语言不再是单一固定句式；
- Validation 使用确定性的 held-out phrase，保证可重复；
- 训练和验证短语集合无交叉。

7.4 模型语言路径

- DistilBERT 继续冻结，保持轻量和稳定；
- Language Projection Layer 参与训练；
- 原始 instruction 文本完整送入 tokenizer/DistilBERT；
- 没有用字符串哈希直接生成动作；
- evaluator 可显式指定 task_type 和 target_id 来构建正确仿真任务；
- 该显式元数据只用于环境任务配置，不替代文本进入模型。

7.5 防止任务阶段家族混淆

新增或加强：

- phase family supervision；
- pick 与 push 的阶段类别约束；
- target class 和 target position grounding 监督；
- 恢复阶段的目标选择监督。

目标是避免第一次失败后从“抓取”错误切换到“推动”，或反向切换。

7.6 当前语言能力的正确表述

V3 已经比固定六句模板更接近真实语言条件策略，但目前可以确认的是：

- 在项目定义的抓取/推动/颜色/形状语义域内具备同义表达泛化；
- held-out phrase 与训练 phrase 分离；
- 不是简单固定句式查表。

目前还不能宣称：

- 具备开放世界语言理解；
- 能理解任意新任务；
- 已达到通用大模型级语义推理。

8. V3 模型与训练策略
===============================================================================

8.1 保守升级原则

为保持可归因性，V3 没有同时大改所有模型结构：

- 继续使用 chunk_size=20；
- 继续使用 5 步 state history；
- 继续使用 V2 Clean 的核心 MiniVLA 架构；
- 继续使用相同动作定义和归一化方式；
- 重点改变数据分布、语言采样、phase family 监督和恢复能力。

8.2 Warm Start

V3 使用 V2 Clean 完整策略权重 warm start，而不是从零训练：

- 视觉骨干继承；
- 语言路径继承；
- grounding 继承；
- Transformer 和动作头继承；
- 使用完全相同的 V2 normalization statistics。

这样做的目标：

- 保留 V2 已经成熟的 Clean 操作能力；
- 只用更低学习率吸收恢复数据和语言多样性；
- 降低一次训练造成灾难性退化的风险。

8.3 训练脚本与关键配置

新增：

- scripts/train_v3.py
- scripts/preflight_v3.py
- hpc/train_v3.sbatch
- docs/runbooks/V3_RUNBOOK.md

主要配置：

- 训练 epoch：30；
- 主学习率：2e-5；
- 视觉骨干学习率：5e-7；
- phase family loss weight：0.35；
- V2 Clean 与 V3 Recovery 混合训练；
- 训练语言动态增强；
- Validation 使用 held-out language；
- checkpoint 按综合 selection score 选择。

8.4 Preflight

训练前检查全部通过：

- V2 Clean 数据未被修改；
- V3 Recovery 数量、任务和平衡正确；
- 语言训练/held-out 无泄漏；
- DataLoader 能跨 episode、跨任务混洗；
- 首个 batch 包含 16 个 episode、全部六任务和 30 条不同语言；
- normalization 只基于训练数据；
- full warm start 成功；
- CUDA forward/backward smoke test 通过。

11. 当前遗留问题与风险
===============================================================================

11.1 Push B 仍是最弱任务

V3 Push B 为 92.5%，比 V2 低 2.5 个百分点。剩余失败包括：

- 一次推动距离约 6.43 cm，接近但未过成功阈值；
- 一次错误接触绿色圆柱；
- 该错误接触回合 grounding mean 约 2 cm、max 约 5.4 cm；
- 同一回合发生 15 次 grounding reset。

判断：

- 蓝球本身的接触和滚动更敏感；
- 场景拥挤时仍可能发生目标跟踪漂移；
- 频繁 reset 只能停止旧动作，不能自动修复错误目标选择。

11.2 Push C 横向偏移

两次失败的前向距离已经足够：

- 8.85 cm；
- 9.25 cm。

但横向误差过大：

- 7.24 cm；
- 8.60 cm。

判断：

- 模型能找到并推动圆柱；
- 主要失败是方向控制，而不是接触不到；
- 需要后续在扰动测试中区分 insufficient distance 和 lateral error。

11.3 Action clipping 略有增加

V3 action clip rate 从 6.89% 增至 7.76%。虽然没有造成整体退化，但提示：

- 某些恢复动作更激进；
- 后续动态瞬移时可能放大控制饱和；
- 需要在鲁棒性曲线中同时报告成功率和 clip/safety 指标。

11.4 语言泛化仍需正式测试

训练日志只证明 held-out language validation 正常，Clean 配对测试主要证明任务执行
能力。仍需单独设计：

- 每任务多条未见自然表达；
- 相同场景更换措辞；
- pick/push 动词互换对照；
- 目标颜色和形状最小对照；
- 早期夹爪动作和 phase family 监控。

11.5 动态瞬移问题尚未由 V3 正式闭环验证

V3 的恢复数据正是为该问题设计，但当前正式结论仍然只是 Clean：

- V3 Clean 已显著优于 V2；
- 不能由此直接推出 4 cm 瞬移也更强；
- 必须跑同 seed、同 level、同 temporal 模式的配对 robustness test。

11.6 ACT chunk_size 的结论仍未完成

当前保留 chunk_size=20 是为了控制变量。尚未证明：

- chunk 越小一定越鲁棒；
- chunk 越大一定 Clean 更好；
- 20 步一定是动态目标失败的主因。

后续必须用 chunk_size=[1, 5, 10, 20]、其余配置完全一致的消融实验回答。


===============================================================================
12. 当前阶段的最终结论
===============================================================================

12.1 已经确认的结论

1. V2 Clean 是一个强基准，但动态恢复和语言多样性不足。
2. 旧 Pilot 混有评估协议漏洞，不能直接把失败归因于 ACT 20 步。
3. 动态场景中的主要风险是 OOD grounding、目标选择和失败恢复，而不只是旧动作。
4. 保留 V2 Clean 数据并新增独立恢复数据，比推倒重来更稳妥。
5. V3 恢复数据通过严格质量检查，没有用失败轨迹污染训练。
6. 动态语言增强显著扩大了训练表达，但目前仍是受限任务域语言泛化。
7. HPC 的 CUDA + EGL + MiniVLA 链路已经跑通。
8. V3 在 L40S 上完整训练成功，选取 Epoch 22 checkpoint。
9. V3 在正式配对 Clean 测试中达到 235/240 = 97.92%。
10. 相比同协议 V2 的 92.50%，V3 提升 5.42 个百分点，McNemar p=0.0072。
11. V3 可以作为新的 Clean 候选标准模型。

12.2 还不能下的结论

1. 不能仅凭 Clean 97.92% 宣称动态鲁棒性已经解决。
2. 不能仅凭冻结 DistilBERT 和同义句增强宣称开放世界语言理解。
3. 不能仅凭 6/6 Postflight 宣称总体成功率。
4. 不能在没有 chunk ablation 的情况下断言 20 步就是最优或最差。
5. 不能忽略 Push B、Push C 横向偏移和 action clipping 的剩余风险。

13. 下一阶段建议执行顺序
===============================================================================

阶段 A：V3 Held-out Language Evaluation

- 六任务分别测试多条 held-out phrase；
- 固定场景只改变语言；
- 记录 task success、target class、phase family、early gripper close；
- 检查语言变化是否引起动作语义切换。

阶段 B：V2/V3 Dynamic Displacement 配对评估

- levels：0、0.02、0.04 m，之后再扩展到 0.06、0.08 m；
- 每 level 至少 20 episodes；
- V2 和 V3 使用相同 seed；
- temporal 与 latest-only 都运行；
- 重点记录 reacquisition latency、wrong contact、grounding reset、
  stale prediction age、failure category。

阶段 C：五维鲁棒性衰减曲线

1. Dynamic Target Displacement；
2. Visual Noise / Blur / Brightness；
3. Physics Parameter Drift；
4. OOD Distractor Injection；
5. Camera Extrinsic Shift。

阶段 D：ACT Chunk Ablation

- chunk_size=[1, 5, 10, 20]；
- 相同数据、seed、训练轮数、模型容量和优化器；
- 对比 Clean、4 cm displacement、平均步数和控制平滑性；
- 输出 Clean 与 Robustness 的交叉曲线。

阶段 E：定向修复

只有在上述评估确认后再决定是否重新训练。优先级：

1. Push B 错误目标和近阈值推动；
2. Push C 横向偏移；
3. 高 action clip / safety intervention；
4. held-out language 早期夹爪误判；
5. 大位移下的目标重获取。

15. 一句话阶段总结
===============================================================================

本阶段没有简单地把动态失败归咎于“ACT 20 步太长”，而是先修复评估协议，
再通过诊断确认 OOD grounding 和失败恢复才是主要缺口；随后保留强势的 V2
Clean 基线，新增受严格验证的恢复数据和动态语言增强，在 Cognition L40S 上
完成 V3 训练，并最终以 240 回合严格配对测试证明 V3 Clean 成功率从 92.50%
提升到 97.92%。下一步的核心不再是盲目重训，而是正式测绘动态瞬移、语言
泛化和其他物理/视觉干扰下的性能衰减曲线。
